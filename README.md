# 单机数据包报告生成器（GenPaper）

基于 Excel 数据和 Word/Excel 模板的自动化报告生成工具。全部文件在内存中处理，不落盘；生成的报告由浏览器弹出保存对话框。

## 运行

```bash
# 安装依赖（Python 3.9+）
pip install -r requirements.txt

# 启动
cd web-app
python app.py
# 访问 http://127.0.0.1:5000
```

## 功能

- **报告生成**：上传 Excel 数据文件 + Word/Excel 模板，选择批次号，一键生成报告。
- **数据一致性对比**：勾选多个批次与参数，生成对比 Word 报告并给出一致性结论。

## 数据文件格式约定

数据 Excel 需包含名为 `数据` 的 sheet（优先精确匹配，其次名称包含"数据"）：

- 第 0 行：从第 3 列（D 列）起为批次号；
- 第 1 行：表头（B 列 `ID`、C 列 `Description`）；
- 第 2 行起：B 列参数 ID，C 列描述，D 列起为各批次的参数值。

可选 `文档` sheet（分组表头在第 0 行，第 1 行为 `ID` / `Number` / `Name` 三列一组）：

- 组名为 `字母-数字` 形式（如 `Z01-1`）的列组识别为**单机文档**（按批次组织）；
- 其余列组识别为**通用文档**。

> 批次列允许不连续：参数取值按批次号实际所在列对应，不连续时服务端日志会给出警告。

## 模板占位符规则

- `{{参数ID}}`：替换为该批次下的参数值；
- `{{文档ID}}`（如 `{{Doc_3}}`、`{{Fxt_4}}`、`{{Sj_12}}`）：替换为 `文档编号《文档名称》`；
  - 前缀属于单机文档批次组的按批次查询，其余查通用文档，批次中不存在时回退通用文档；
- `{{ doc('文档ID') }}`：docxtpl 函数形式，效果同上；
- Word 模板同时支持 `.docx`，Excel 模板仅支持 `.xlsx`（`.xls` 模板为保留原样式不支持直接编辑）。

### 约束与已知限制

1. **参数 ID 命名**：Word 模板路径以参数 ID 作为 Jinja2 变量名，需为合法标识符（字母/下划线开头，仅含字母、数字、下划线，如 `N003_001_1`）。含 `-`、`.`、空格的 ID 无法在 Word 模板中通过 `{{...}}` 引用（解析时会输出警告；Excel 模板路径无此限制）。
2. **多行参数值**：Word 输出中的换行会渲染为软换行（`<w:br/>`）；Excel 输出保留原始换行（需单元格开启自动换行才能显示）。
3. **Excel 模板对象**：openpyxl 保存会丢失模板中的图表/图片/绘图对象（存在时服务端日志会警告）；公式单元格不做替换以保护公式结构。
4. **一致性判定口径**：字符串精确比较（strip 后）；空值不参与判定；数值格式差异（`1.0` 与 `1.00`）会判为"不一致"，报告末尾会注明空值数量。
5. **文件缓存**：上传的文件按内容 MD5 去重缓存在内存中，超过 30 分钟未使用过期，缓存上限 20 个文件；服务重启后需重新上传。

## 工程结构

```
web-app/
├── app.py                  # Flask 后端（API + 静态文件服务）
├── report_generator.py     # 核心模块：Excel 解析 / Word、Excel 报告生成 / 一致性对比
└── frontend/
    └── dist/               # 前端（唯一前端实现，vanilla JS，由 Flask 直接服务）
        ├── index.html
        └── app.js
templates/                  # 模板样例（Doc_3.docx / xls_1.xlsx）
单机数据包（公开）.xlsx       # 数据样例
```

- 前端为手写的 `dist/` 静态实现，**不存在独立的前端构建步骤**；修改前端直接编辑 `dist/` 下的文件。
- Word 生成采用双层替换：docxtpl 主路径 + ZIP/XML 层文本框兜底（值统一在构建上下文时做 XML 转义）。
- 日志输出到 stdout/stderr（logging），错误详情见服务端日志，接口只返回简短提示。
